# Capture a conversation reflection

Follow [vault access](../../references/vault-access.md). Read the vault's conversation-reflection or person-note template according to what the user is recording.

If the user wants help remembering but has supplied no account, ask one short open question such as "What stayed with you from the conversation?" Follow their response rather than presenting every template field as a questionnaire. A debrief-only request stays in chat. An explicit request to record, save, or add a note authorizes a new file in Conversations.

When saving, retain the user's supplied words in a clearly marked account section. Add only practical metadata outside that section, such as the names, written date, and conversation date if known. Preserve hedges, approximate dates, and the difference between what was said and the user's impression. Do not fill gaps with facts from earlier notes. For speech-like fragments, keep them as fragments unless the user requests editing.

For existing knowledge, label the file a person note and omit any invented conversation date. For a reflection, record an unknown conversation date as unknown. If the user requests a polished summary, preserve the original account alongside the requested summary and label which is which.

Use a new Windows-safe filename and a numeric suffix if it already exists. Read the saved note back and confirm that its account preserves the supplied text. Link the note in the response. Do not also refresh derived memories unless that was part of the request; mention the refresh skill only if useful.

Treat a reported promise as an offer, not evidence that the user fulfilled it. A hypothetical answer, suggested question, or imagined dialogue is not something the friend actually said.
