# Refresh derived context

Follow [vault access](../../references/vault-access.md). Read the vault workflow's refresh and corrections sections and its context-note template. Those sections define candidate, approval, rejection, and freshness behavior.

Scope the refresh to the people or notes named by the user. A request to refresh the whole vault covers all Conversations notes. Read original evidence and the current context before writing. State incomplete coverage rather than claiming to have synchronized the whole collection.

Update existing person pages and useful shared-entity pages. Keep each shared claim attributed to its source and date. Do not move personal confidences into a shared page simply because they concern the same workplace. Follow explicit approvals and rejections; new derived details remain candidates.

Separate correction from later life change. Preserve conflicting accounts with links, continue with undisputed information, and ask for clarification only where it affects interpretation. If supporting evidence changed or disappeared, apply the vault's review and stale-card rules.

Reread existing files immediately before editing. Preserve user annotations and avoid duplicate facts on repeated refreshes. Raw Conversations files remain unchanged unless the user separately asked to correct or record them. Do not silently delete historical cards.

Finish with a short list of updated files, candidates needing review, unresolved conflicts, and affected cards. Include the files read or a concise source-coverage statement. No background monitoring is established by this skill.
